`frost_sta_client` is a pure-Python package distributed on [PyPI](https://pypi.org/project/frost-sta-client/) and installable with a single `pip` command. This page covers all installation variants, the full dependency list, notes on the JSON serialisation backend, and how to run a complete local FROST-Server stack for development using Docker Compose.

## Requirements

- **Python 3** (any maintained 3.x release)
- **pip** (comes bundled with Python 3.4+)
- Docker and Docker Compose (only needed for the local server setup)

## Installing via pip

### Latest release

```bash
pip install frost_sta_client
```

This installs the latest stable release from PyPI along with all required dependencies.

### Specific version

Pin to an exact version to ensure reproducible environments across team members and CI pipelines:

```bash
pip install frost_sta_client==1.1.53
```

<Tip>
  Consider committing a `requirements.txt` or `pyproject.toml` with pinned versions to keep your environment stable across deployments. See [Version Pinning](#version-pinning) below for a recommended approach.
</Tip>

### Inside a virtual environment (recommended)

It is good practice to install `frost_sta_client` inside a dedicated virtual environment to avoid conflicts with system packages:

```bash
python3 -m venv .venv
source .venv/bin/activate      # macOS / Linux
.venv\Scripts\activate         # Windows

pip install frost_sta_client
```

## Dependencies

When you install `frost_sta_client`, pip automatically installs the following dependencies:

| Package | Minimum version | Purpose |
|---------|----------------|---------|
| `requests` | ≥ 2.26.0 | HTTP transport for all API calls |
| `furl` | ≥ 2.1.3 | URL construction and query-string manipulation |
| `geojson` | ≥ 2.5.0 | GeoJSON geometry objects used in `Location` entities |
| `jsonpickle` | ≥ 2.0.0 | JSON (de)serialisation of Python entity objects |
| `demjson3` | ≥ 3.0.5 | High-precision float JSON backend (default) |
| `jsonpatch` | any | JSON Patch support for partial entity updates |
| `python-dateutil` | any | ISO 8601 date/time parsing for temporal fields |

<Note>
  The `requirements.txt` in the repository also lists `jsonpickle<=2.2.0` as an upper bound to protect against breaking API changes in the serialisation layer. If you encounter unexpected serialisation errors after upgrading `jsonpickle`, downgrade to `2.2.0`.
</Note>

## JSON Backend: `demjson3` vs `json`

`frost_sta_client` uses [jsonpickle](https://github.com/jsonpickle/jsonpickle) for serialising Python entity objects to JSON and back. `jsonpickle` supports multiple pluggable JSON backends.

By default the library registers and activates `demjson3` as the preferred backend:

```python
# This happens automatically when you import frost_sta_client
import jsonpickle

jsonpickle.load_backend('demjson3', 'encode', 'decode', 'JSONDecodeError')
jsonpickle.set_preferred_backend('demjson3')
jsonpickle.set_decoder_options("demjson3", decode_float=float)
```

The reason is that sensor readings often involve high-precision floating-point numbers (e.g. `23.456789012`). The standard library `json` module may silently round such values, whereas `demjson3` preserves full precision.

### Switching to the standard `json` backend

If you do not need high-precision float handling, or if `demjson3` causes compatibility issues in your environment, you can switch to the standard backend at any point **after** importing `frost_sta_client`:

```python
import frost_sta_client as fsc
import jsonpickle

# Override the default demjson3 backend
jsonpickle.set_preferred_backend('json')
```

<Warning>
  Call `jsonpickle.set_preferred_backend` **after** `import frost_sta_client`, because the import itself sets `demjson3` as the preferred backend. Calling it before import will have no lasting effect.
</Warning>

## Setting Up a Local FROST-Server with Docker Compose

For local development and testing, the repository ships a `docker-compose.yaml` at `frost_server/docker-compose.yaml` that launches a fully configured FROST-Server instance backed by a PostGIS database.

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) or Docker Engine with the Compose plugin installed.

### Start the server

```bash
# From the root of the FROST-Python-Client repository
docker compose -f frost_server/docker-compose.yaml up -d
```

Docker will pull `fraunhoferiosb/frost-server:latest` and `postgis/postgis:16-3.4-alpine` on first run. The FROST-Server container waits for the database to pass a health check (`pg_isready`) before starting, so the services come up in the correct order automatically.

### Services started

| Service | Image | Ports |
|---------|-------|-------|
| `web` (FROST-Server) | `fraunhoferiosb/frost-server:latest` | `8080` (HTTP), `1883` (MQTT) |
| `database` (PostGIS) | `postgis/postgis:16-3.4-alpine` | internal only |

Once running, the SensorThings API root is available at:

```text
http://localhost:8080/FROST-Server/v1.1
```

### Default configuration

The compose file pre-configures the server with the following settings:

```yaml
serviceRootUrl: http://localhost:8080/FROST-Server
plugins_multiDatastream.enable: false
http_cors_enable: true
http_cors_allowed_origins: "*"
auth_provider: de.fraunhofer.iosb.ilt.frostserver.auth.basic.BasicAuthProvider
persistence_db_url: jdbc:postgresql://database:5432/sensorthings
```

Basic authentication is enabled. The default database credentials are `sensorthings` / `ChangeMe`. Update the `environment` section of the compose file before deploying to any shared environment.

<Warning>
  Change the default passwords (`ChangeMe`) before exposing the server on a network. The compose file is designed for local development only.
</Warning>

### Enable MultiDatastreams

To use the `MultiDatastream` entity type, set `plugins_multiDatastream.enable` to `true` in the compose file's `environment` section before starting:

```yaml
environment:
  - plugins_multiDatastream.enable=true
```

### Connect from Python

Once the server is running, connect with basic auth credentials:

```python
import frost_sta_client as fsc

service = fsc.SensorThingsService(
    "http://localhost:8080/FROST-Server/v1.1",
    auth_handler=fsc.AuthHandler(username="admin", password="admin")
)
```

### Stop and clean up

```bash
# Stop containers (keeps the database volume)
docker compose -f frost_server/docker-compose.yaml down

# Stop and delete all data (removes the postgis_volume)
docker compose -f frost_server/docker-compose.yaml down -v
```

## Version Pinning

For production and CI environments, pin both `frost_sta_client` and its key dependencies to avoid unexpected breakage from upstream releases. A minimal `requirements.txt` might look like:

```text
frost_sta_client==1.1.53
requests>=2.26.0,<3.0
jsonpickle>=2.0.0,<=2.2.0
demjson3>=3.0.5
furl>=2.1.3
geojson>=2.5.0
jsonpatch
python-dateutil
```

Generate a fully-locked file from your working virtual environment with:

```bash
pip freeze > requirements-lock.txt
```
